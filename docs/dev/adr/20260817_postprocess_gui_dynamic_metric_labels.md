# ADR: 位況・流況後処理GUIと対象種別ラベルの動的化

## 状態

Accepted

## 背景

後処理は水位を前提にしたExcel表示ラベルを持っている一方、計算自体は値列を汎用的に扱える。流量データを処理すると、流量に対して「水位」と表示されるため、GUI追加時に対象種別と表示ラベルの対応を整理する必要がある。

## 決定

- 後処理GUIでは対象種別として水位と流量を明示的に選択する。
- ファイル名からの種別判定は初期値の提案に限定し、ユーザーの選択を正本とする。
- 対象種別ごとの単位・位況/流況名・ピーク名・集計見出しは、専用の定義モジュールから生成する。
- 内部計算列名は既存互換のため変更しない。
- 既存ランチャーには独立した`postprocess`アプリとして登録する。取得GUIへ処理画面を直接混在させない。

## 理由

- 水位と流量で「位況/流況」「水位/流量」の表記が変わるため、画面側の個別置換ではなく一元定義が必要になる。
- ファイル名だけでは誤指定を訂正できないため、明示選択を正本にする方が安全である。
- 取得と後処理を分けることで、既存の取得処理・CLI・出力形式への影響を抑えられる。
- ランチャー統合なら既存のアプリ間ナビゲーションと終了制御を再利用できる。

## 影響

- CLIは`--metric`を追加するが、省略時は水位として後方互換を保つ。
- Excelの表示見出しは流量処理時に流況・流量表記へ変わる。
- 雨量の取得機能は既存GUIに残し、今回の位況・流況後処理GUIには追加しない。
