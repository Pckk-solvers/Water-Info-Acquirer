# ダム諸量の取得調査とGUI対応案

調査日: 2026-10-27。実装前の調査記録。後続でユーザーの実装承認を受領した。
現行仕様は [ダム諸量の要件](../requirements/water_info-dam.md)、構成は [ダム諸量の設計](../architecture/water_info_dam.md) を参照。

## 対象と結論

- 観測所記号: `608061288803010`
- 観測所名: 長安口ダム（ながやすぐちだむ）
- 水系・河川: 那賀川
- ダム専用ページから過去の時間値、直近の10分値ともHTTP 200で取得できた。
- 現行アプリは水位・流量・雨量の単一項目を扱う。ダム専用URL、複数項目、属性を扱う経路がなく、GUI対応には追加実装が必要。
- 最初に試した `SiteInfo.exe` は403だったが、ダム専用ページは取得可能だった。観測所情報ページの応答だけではダムデータの取得可否を判断できない。

## 公式の取得経路

1. [任意期間検索](https://www1.river.go.jp/cgi-bin/SrchDamData.exe?ID=608061288803010&KIND=1&PAGE=0)
2. 検索画面の `/js/SrchDamData.js` が次のURLを開く。

```text
https://www1.river.go.jp/cgi-bin/DspDamData.exe?KIND=1&ID=608061288803010&BGNDATE=20240101&ENDDATE=20240131&KAWABOU=NO
```

- 開始・終了は `YYYYMMDD`。`PAGE=0` は上記期間検索の生成URLには含まれない。
- 検索画面は「最大31日」と表示する。クライアント側の日数検証には月の扱いなど注意点があるため、そのJavaScriptを日付計算の正本としてコピーしない。
- 結果ページにはダウンロード用 `.dat` と実表の `iframe` がある。
- ダウンロードURLとiframe URLは結果ページから都度解決する。時刻・生成IDを含むため固定しない。
- ダウンロードはCSV形式のテキストで、CP932で読めた。実表はEUC-JP。親ページは今回、実バイト列がEUC-JPなのにmetaにはUTF-8と書かれていた。ヘッダーだけで決め打ちせず文字化け検知・fixture確認が必要。
- `.dat` は値と属性を対にして持つため、取得元の第一候補とする。iframeは比較検証に使った。

[リアルタイム一覧](https://www1.river.go.jp/cgi-bin/DspDamData.exe?ID=608061288803010&KIND=3&PAGE=0) は別経路。今回の実測では10分値で、iframeが新しい時刻から古い時刻、ダウンロードが古い時刻から新しい時刻の並びだった。過去の時間値と自動混合しない。

## 項目と単位

| 項目 | 元ページの単位 | 整理時の注意 |
| --- | --- | --- |
| 流域平均雨量 | mm/h | 点雨量と区別。時間値と10分値の積算・平均の意味は別途確認 |
| 貯水量 | ×10³ m³ | 単位画像を目視確認。画像ファイル名から倍率を推定しない |
| 流入量 | m³/s | 通常観測所の流量と別の項目名で保存 |
| 放流量 | m³/s | 流入量とは独立して保存 |
| 貯水率 | % | 元値と単位を保持 |

今回の長安口ダムの表に「貯水位」はなかった。他ダムにもないとは断定せず、未知の列が出た場合の検知を設計する。

## 実データ検証

| 指定した元日付 | 時間値行数 | 正規化後の先頭 | 正規化後の末尾 |
| --- | --- | --- | --- |
| 2024-01-01〜2024-01-31 | 744 | 2024-01-01 01:00 | 2024-02-01 00:00 |
| 2024-02-01〜2024-02-02 | 48 | 2024-02-01 01:00 | 2024-02-03 00:00 |
| 2026-10-20〜2026-10-21 | 48 | 2026-10-20 01:00 | 2026-10-22 00:00 |

- 全840行で、日時と5項目をダウンロード・iframe間で照合した。
- 各期間で日時は昇順・重複なし・1時間間隔だった。
- `24:00` は翌日 `00:00`。月末分も保持する。既存の時間意味ルールと整合する。
- `.dat` の説明には `$:欠測`、`-:未受信` がある。この2種類の実例は今回の標本にはなかった。
- 2024-01-31 10:00、11:00の貯水量・流入量・放流量・貯水率は、ダウンロードで原値0と属性 `#`、iframeで「閉局」だった。計8項目値を通常の0として扱ってはいけない。
- 数値だけで欠測を判定せず、項目ごとの属性を保持する。未知の属性は通常値へ黙って変換しない。

## GUI案

- 取得対象を「水位・流量・雨量」「ダム諸量」で切り替える。水位・流量・雨量の個別選択とは別に置く。
- 水位・流量・雨量では従来の3項目を選択する。ダム諸量では5項目を一括取得し、流入量だけなどの取得指定を要求しない。
- ダムの入力は観測所記号、開始日・終了日、出力先、Parquet出力の有無を基本とする。日まで指定できるようにする。
- 初期対応は任意期間検索の時間値。ダム選択時に既存の「日データ」を適用しない。10分値は別機能として後続検討する。
- 31日を超える期間は内部で開始日・終了日を含め31日以内の窓へ自動分割し、利用者に手分割を求めない。
- 結果には取得行数、項目別の有効・欠測・未受信・閉局件数、取得失敗区間を表示する。途中失敗を全期間成功と表示しない。

## 整理・出力案

1. **時間値一覧**: 1日時1行に5項目を横並び。観測所記号、元日付・時刻、正規化日時と各項目の品質を保持する。
2. **品質一覧**: 項目ごとの欠測・未受信・閉局件数、期間の行欠落、失敗区間を出す。
3. **出典**: 観測所名、水系・河川、要求期間、取得日時、取得種別、単位、分割窓とURLを記録する。
4. **機械可読形式**: Parquetは流入・放流を別metricにし、元属性を失わない契約を要件・設計で決める。既存の水位・流量用の変換をそのまま呼ばない。
5. **日別・期間集計は後続候補**: 流入・放流の最大値と時刻、貯水量・貯水率の最小最大など。雨量合計、流入・放流の積分量、日平均は時間意味と欠測時の成立条件を決めてから追加する。

## 実装前に確定する事項

- 時間値の流域平均雨量が表す区間、流入量・放流量が瞬間値か平均値か。単位だけから確定しない。
- 日付選択の意味は元ページの日付範囲とし、末尾24時は出力に残す案。正規化日時の暦日で再抽出して切り落とさない。
- 複数ダムで列構成・属性・提供期間に差がある場合の扱い。
- 日データや10分値の初期スコープへの追加要否。まず時間値に限定する案。
- 既存Parquet契約・グラフ・位況流況後処理への対応は自動的に付随しない。別途契約確認が必要。
