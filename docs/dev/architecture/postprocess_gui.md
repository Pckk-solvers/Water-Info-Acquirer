# 位況・流況後処理GUIの構成

## 目的

取得済みの水文水質データを対象に、位況・流況の後処理をGUIから実行する。既存の後処理計算を再実装せず、GUIは入力・対象種別・出力先の指定と実行制御を担当する。

## 画面構成

```text
┌──────────────────────────────────────────────┐
│ 水文統計（位況・流況）                         │
├──────────────────────────────────────────────┤
│ 対象種別     [水位（位況） ▼]                  │
│              出力ラベル例: 位況豊水位 ...       │
│                                              │
│ 時間データ   [ファイルパス             ][参照] │
│ 日データ     [任意のファイルパス       ][参照] │
│ Excel出力    [ファイルパス             ][参照] │
│ [ ] Parquet出力 [ディレクトリ           ][参照] │
│                                              │
│ [実行]                                       │
│ 状態: 未実行                                  │
├──────────────────────────────────────────────┤
│ 入力説明・対象種別ごとの注意事項               │
└──────────────────────────────────────────────┘
```

## 責務分割

- `src/water_info/postprocess_labels.py`
  - 対象種別の定義、単位、位況/流況名、Excel表示ラベルを一元管理する。
- `src/water_info/postprocess.py`
  - 既存の読込・集計・ランク・位況計算・出力を担当する。
  - `metric`を受け取り、表示ラベルだけを対象種別に応じて切り替える。
- `src/water_info/postprocess_service.py`
  - GUIから利用する後処理実行リクエストの境界を提供する。
  - バックグラウンドスレッドからCLIパーサーを直接操作せず、後処理入口を呼び出す。
- `src/water_info/ui/postprocess_app.py`
  - Tkinter画面、ファイルダイアログ、入力検証、バックグラウンド実行、結果表示を担当する。
- `src/water_info/postprocess_launcher_entry.py`
  - トップレベルランチャーからGUIを開く薄い入口を担当する。
- `src/water_info_acquirer/app_registry.py`
  - `postprocess`を既存ランチャーへ登録する。

## 動的ラベルの流れ

1. GUIの対象種別選択値を`water_level`または`discharge`として保持する。
2. `_WH`/`_QH`のファイル選択時は初期値候補だけを補助的に設定する。
3. 対象種別の変更イベントで、画面説明とラベル例を更新する。
4. 実行時に同じ対象種別を後処理へ渡す。
5. 後処理は対象種別定義から`main`、`peaks`、`summary_adj`、`summary_raw`のExcel見出しを生成する。

計算処理の内部列名（`ikyo_high`等）は既存互換のため維持し、表示名だけを動的化する。

## 入出力境界

- 入力: GUIで選択したローカルの`_H` Excel、任意の`_D` Excel。
- 出力: 指定したExcel、任意のParquetディレクトリ。
- ネットワーク取得: 行わない。取得は既存の水文データ取得GUIの責務とする。
- 実行: Tkinterのイベントスレッドをブロックしないようワーカースレッドで実行し、結果だけをTkイベントループへ戻す。

## 既存アプリへの統合

- 既存ランチャーに「水文統計（位況・流況）」のカードを追加する。
- 各既存GUIのメニューからも同じ`postprocess`キーで遷移できる。
- 後処理GUIを既存の水文データ取得GUIへ直接埋め込まず、ランチャー上の独立アプリとして統合する。
