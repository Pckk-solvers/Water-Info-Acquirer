# ダム諸量の構成

関連要件: [ダム諸量のGUI取得・整理](../requirements/water_info-dam.md)

## 責務

- `domain/dam.py`: 要求・項目定義・31日以内かつ同月の窓の計算。
- `infra/dam_parser.py`: CP932の配布CSVとEUC-JPの結果ページを解析。観測所とヘッダーを確認し、時刻と原値・属性を正規化。
- `service/dam.py`: 直列取得、結果ページから同一公式サイトの配布リンクを解決、正常に解析した原データのキャッシュ、失敗記録、要求期間の時間行への整列。
- `infra/dam_writer.py`: 1冊のExcel内の年別時間値・品質・出典シート、全期間CSV、任意Parquet、品質・出典JSON。GUI依存なし。
- `ui/forms.py`: ダム専用の日付条件フォーム。`ui/dam_panel.py` はフォームの互換名のみ。
- `ui/app.py`・`service/acquisition.py`: 「水位・流量・雨量」「ダム諸量」の表示切替、共有の出力先・実行・進捗・中止・結果表示。要求モデルは対象ごとに分離する。詳細は [取得GUIの構成](water_info_gui.md)。

## データフローと出力契約

1. GUIが日付とコードを検証して `DamRequest` を作る。
2. サービスが月単位（最大31日、両端含む）の窓を計算する。
3. 結果ページの配布URLから原データを取得する。キャッシュは観測所・窓ごとの名前で区別し、再利用時も同じ解析・期間検査を行う。
4. 各元日について01:00〜24:00の行を確保し、欠落には `row_missing`、失敗窓には `fetch_failed` を付ける。元データにある属性は項目ごとに保持する。
5. 正規化日時を昇順にし、元日付の年でExcelのシートを分ける。ブックは観測所・要求期間ごとに1冊。年別品質・全期間品質・出典・全取得区間も同じブックに収録する。

横持ち表は `station_code`, `source_date`, `source_time`, `datetime` と、各項目の値・`_raw`・`_attribute`・`_quality` 列を持つ。貯水量の値は元単位の10^3 m3のままとする。
metricは `basin_rainfall`, `storage`, `inflow`, `outflow`, `storage_rate`。品質は `normal`, `missing`, `unreceived`, `closed`, `unknown`, `row_missing`, `fetch_failed`。
ダム用Parquetはこの横持ち表を保存し、既存の統一Parquet契約・グラフ読込へ無条件には接続しない。単位と列定義は出典JSONにも保存する。

## 失敗・中断

- 不正ヘッダー、別観測所、期間外・重複時刻、異なる列構成は成功として処理しない。
- 窓ごとの失敗は記録して次の窓へ進み、最終状態をpartialとする。
- ユーザー中止は残りのネットワーク取得を止め、既取得分と未取得区間を出力してcancelledとする。
- 閉局などの公開データ品質と通信失敗は別集計とする。全件の取得に成功しても欠測がある旨は表示する。
- 原データキャッシュと出典を同時に保存し、再実行で取得済みの窓を再利用する。
